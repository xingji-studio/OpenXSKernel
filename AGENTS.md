## OVERVIEW

OpenXSKernel is the **pure kernel** (kernel-only) extracted from OpenXJ380. It builds a
single artifact, `out/kernel.krl`, and owns **no** bootloader, no userspace applications,
no package manager, and no vendored third-party source. Those live in sibling repositories
(OpenXSBoot, LeopardOS, the `leopard-*` / `*-xbps` component repos).

The build graph is generated by `tools/gen_ninja.py`; the only first-class targets are
`build` (→ `out/kernel.krl`) and `pack` (→ xbps package, gzip-compressed).

---

## RED LINES — read first, highest priority

### 1. 内核只收原语，不收具体业务 (kernel = primitives only, never business)

The kernel provides **mechanisms and primitives**; it must not encode any
**distribution / application / product-specific policy**. Concretely:

- ✅ **In scope (primitives):** syscalls themselves (open/read/write/fstat/mount/brk/…),
  filesystem drivers, VFS node/alias primitives, VFAT name normalization (illegal-char
  handling, LFN), memory/task/interrupt/driver subsystems.
- ❌ **Out of scope (business):** specific distro filenames (e.g. an xbps key filename as a
  hardcoded VFS alias), specific application paths (shell.elf, installer, …), GUI window/
  button/scrollbar APIs, user-registry formats, or per-process-name debug tracing
  (`strstr(name, "xbps")`).

Where business policy must exist, it belongs in **userspace** (LeopardOS / component repos),
driven through generic kernel primitives — never hardcoded in the kernel.

### 2. 上游原版 bug 不改 (do not fix upstream bugs)

Diagnose first, attribute second, then act. If the root cause is in **upstream OpenXJ380 /
OpenXSKernel original code**, leave it unchanged and **stop** — do not fix it. Only fix bugs
introduced by your own changes. Temporary diagnostic prints must be reverted after triage.

### 3. 强制警告 (mandatory warning)

**When a developer (or you) attempts to add non-primitive business logic into the kernel,
warn the developer immediately and stop.** Do not silently accept, refactor, or "clean up"
such a change into shape — flag it first.

├── driver/            # Built-in drivers linked into kernel.krl

├── tests/             # Host-side Python tests (e.g. test_pty_input.py)
├── tools/             # gen_ninja.py — canonical build graph generator
├── docs/              # Architecture/build/development notes
├── linker.ld          # Kernel link script (ENTRY(KernelMain))
├── liballoc-x86_64.a  # Prebuilt third-party allocator (wrapped at link time)

Not present (by design): `boot/`, `kmod/`, `third_party/`, `user/` (top-level),
`Bf/`, `resources/`, `graphics/`. Those were OpenXJ380 and are now separate repos or removed.

## SYSCALL SURFACE

- **Linux ABI** (`SYS_*`): the POSIX-ish surface user-space static binaries (musl, xbps,
  busybox) link against — `open/read/write/fstat/newfstatat/mount/brk/mmap/…`.
- **XAPI** (`XAPI_*`): legacy OpenXJ380 application API. The **GUI subset**
  (`XAPI_CREATE_WINDOW`, `XAPI_DRAW_*`, `XAPI_BUTTON`, scrollbars, text inboxes, …)
  is stubbed to `-ENOSYS` — the syscall numbers are kept for ABI surface but the
  implementation is removed. Non-GUI XAPI (`GET_VERSION` `GET_TIME` `SLEEP`
  `GET_CURRENT_USER` `RUN` `POWER_ACTION` `GET_TASK_LIST` `KILL_PROCESS` …) remains.
- Wiring a syscall: keep three signatures in sync — `sys.cpp` implementation,
  `include/syscall/syscall.h` declaration, `syscall.cpp` dispatch `case`.

## CONVENTIONS

- Freestanding: `-nostdlib -ffreestanding -fno-builtin -fno-stack-protector -fno-rtti`
  `-fno-exceptions -mno-red-zone -m64`; kernel C++ is GNU++17, root C is C11.
- `.S` via clang, `.asm` via NASM. Link via `ld -T linker.ld --static` with
  `--wrap=malloc/calloc/free/realloc/aligned_alloc` (IRQ-safe allocator wrappers).
- `liballoc-x86_64.a` is a prebuilt third-party library; do not rebuild or edit locally.
- `kernel/build_config.h` and `build.ninja` are generated — never hand-edit.
- Keep mandatory core code in `kernel/`; built-in drivers in `driver/`.

## ANTI-PATTERNS (THIS PROJECT)

- Do not hardcode distro/application policy in the kernel (see RED LINE 1).
- Do not add a syscall or VFS alias that encodes a specific filename or pathname.
- Do not fix upstream OpenXJ380 bugs (see RED LINE 2); attribute first.
- Do not dereference user pointers in filesystem/syscall paths without copying at the boundary.
- Do not treat upstream-derived FATFS code as ordinary first-party cleanup territory.
- Do not hand-edit `build.ninja`, `kernel/build_config.h`, or `.clangd`.

## KNOWN DECISIONS / ISSUES (this session)

- **zstd data corruption = upstream lazy-alloc bug, not to be fixed in kernel.**
  zstd's large decompression window trips a memory-corruption bug in upstream
  `kernel/memory/` (byte-identical across OpenXJ380/OpenXSKernel). Workaround decided at the
  userspace layer: compress xbps packages/repodata with **gzip** instead of zstd (done in the
  component `gen_ninja.py` + LeopardOS `build_liveroot.sh`). Do not "fix" the kernel
  allocator here.
- **Colon filenames (FAT):** the correct primitive is VFAT driver-layer name normalization
  (illegal-char handling + LFN), modeled on Linux `fs/fat/namei_vfat.c` — not app-level
  alias registration. OpenXJ380's hardcoded xbps-key VFS alias is the anti-pattern.
- **PID1 decoupled:** kernel reads `BootConfig.init` (boot.conf); no hardcoded shell path.

## 输入路由 + IME kmod 架构（C 方案，2026-10-28 定稿）

精简内核只保留**输入原语 + 通用钩子 + 符号导出**；IME 业务（焦点匹配、事件队列、投递、
会话、配置、词库）全部放进独立仓库 `ime-kmod`（可加载 `.sys`）。

### 输入原语（内核保留）
- sink 注册表 + 焦点表：`include/input_sink.h`、`kernel/input_sink.cpp`。
- 输入流拦截器：`input_route_set_interceptor` / `input_route_interceptor`，签名
  `bool (*)(uint64_t msg_type, uint64_t lData, uint64_t callback, tcb_t task)`。
- 路由/投递：`input_route_dispatch`、`do_message`、`do_message_unfiltered`、`message_getch_try`。
- 消息常量：`MSG_CHAR`/`MSG_KEYDOWN`/`MSG_KEYUP`/`MSG_SPCHAR`/`MSG_KEYLONGPRESS`（`include/syscall/pxapi.h`）。

### VFS 通用保护/解析钩子（内核保留）
- 枚举 `vfs_access_op_t`：`VFS_ACCESS_READ/WRITE/REMOVE/MOUNT`（`include/fs/vfs/vfs.h`）。
- 钩子类型 `vfs_access_hook_t` / `vfs_resolved_name_hook_t`；注册 `vfs_set_access_hook` /
  `vfs_set_resolved_name_hook`（均已导出）。
- 内核内部调用点：`vfs_access_allowed` / `vfs_notify_resolved_name`（无钩子时放行/no-op）。
- `vfs_node.ime_protection` 字段 = 内核态对象策略标记，由 resolved-name 钩子设置。

### pcb/tcb 精简
- 已移除 IME 字段：`ime_role`、`ime_launch_generation`、`ime_config_depth`、
  `ime_storage_depth`、`ime_launch_role`。kmod 不得读写，改用 per-task 侧表 + 静态 pid
  （见 `ime-kmod/AGENTS.md`）。

### 符号导出（EXPORT_SYMBOL / _OBJECT / _F）
- 已导出：vfs 原语、mutex 原语（含 `mutex_lock_recoverable`）、alloc 原语
  （`malloc/free/calloc/realloc/aligned_alloc` 经 `__wrap_*`）、user 原语
  （`current_user`/`rootdir` 对象、`user_session_is_ready`）、`xapi_json_*`、
  page-table 原语（`translate_address`/`page_table_get_flags`/`lazy_tryalloc`）、
  `vfs_set_access_hook`/`vfs_set_resolved_name_hook`。
- dlinker 用 `dlinker_mangled_global_matches` 把 kmod 的 C++ mangled 符号匹配到导出名。

### kmod 加载
- `kmod/ime/ime.cpp` 是占位 skeleton（dlmain 注册空 interceptor + syscall hook）；真实业务在 ime-kmod。
- dlinker 经 `find_export(handle, "dlmain")` 定位入口；`dlmain`/`dlstart` 必须 unmangled +
  `visibility("default")`（编译 flags `-fvisibility=hidden` 下只有它们导出）。
